## 0. はじめに

こんにちは、エンジニア2年目のはなまるです！

以前に、先輩が作った設計を見ていると、ハッシュ化の文脈で「ソルト」や「ペッパー」という文言がありました。
塩とコショウのことだとは分かったのですが、そこまでの知識だったので調査してみました笑

ということで今回は、ハッシュ化が抱える課題と、対策である「ソルト」と「ペッパー」の役割を整理しつつ、PHPでの具体的な実装コードまで理解していきます！

## 1. ハッシュ化の「致命的な課題」とは？

まずは、パスワードを守るための基本である「ハッシュ化」のおさらいです。

ハッシュ化とは、入力データを一定の長さの値に不可逆な文字列変換する技術です。
これを使うと、万が一データベースが漏洩しても、元のパスワードがそのままバレるのを防ぐことができます。

しかし、ハッシュ化には、2つの大きな課題があります。

### 課題①：レインボーテーブル攻撃（同じパスワードを見破られる）

世の中の多くの人は「password123」や「123456」といったよくあるパスワードを使います。
これらをハッシュ化すると、誰がやっても同じハッシュ値になります。
攻撃者は、よく使われるパスワードとハッシュ値の対応表（**レインボーテーブル**）をあらかじめ用意しており、これを見れば元のパスワードを一瞬で見破れてしまうわけです。

### 課題②：ブルートフォース(総当たり)攻撃＆辞書攻撃

複雑なパスワードであっても、計算スピードが速い現代のパソコンを使えば、ありとあらゆる組み合わせを総当たりで試して突破されてしまう危険があります。

## 2. 課題を解決する「ソルト」と「ペッパー」とは？

これらのハッシュ化の弱点を補うために登場するのが、ソルトとペッパーです。
ハッシュ化に調味料を振るイメージで理解してください！

### 【対策まとめ】

先に全体像をざっくり見るとこんな感じです。

| 対策用語 | ざっくり解説 | 保存場所 | 何を防ぐ？ |
| --- | --- | --- | --- |
| **ソルト**  | ユーザーごとランダムな文字列をくっつけてハッシュ化 | データベースに保存 | レインボーテーブル攻撃 |
| **ペッパー** | パスワードに固定文字列をくっつけてハッシュ化 | 環境変数等で管理 | ブルートフォース攻撃 |

### ① ソルトとは？
ソルトとは、パスワードをハッシュ化する直前にくっつける「ユーザーごとに異なるランダムな文字列」のことです。

【例】ソルトの効果

Aさんのパスワード（password123） ＋ ソルト（aB7x!） ＝ ハッシュ値「9f86d...」

Bさんのパスワード（password123） ＋ ソルト（zK9#m） ＝ ハッシュ値「3c2b1...」

同じ「password123」というよくあるパスワードを使っていても、ソルトが異なるため、データベースに保存されるハッシュ値は全く別の文字列になります。
これにより、攻撃者がレインボーテーブルをあらかじめ用意しても、ソルトのせいで一致しなくなり、レインボーテーブル攻撃を無効化できます。

### ② ペッパーとは？
ペッパーとは、ソルトとは異なり、「システム全体で共通の隠し味（固定の秘密文字列）」のことです。これをパスワード（またはソルト付きパスワード）に結合してからハッシュ化します。

【例】ペッパーの仕組み

入力値 ＋ ペッパー（SuperSecretPepper_2026!） ＝ ハッシュ化して保存

最大のポイントは、「ペッパーはデータベースには絶対に保存しない（ソースコードの環境変数などで別管理する）」という点です。
万が一、ハッカーにデータベースが丸ごと盗まれてしまい、ハッシュ値とソルトが両方とも流出したとします。
しかし、ペッパーのデータだけは攻撃者の手元にありません。
攻撃者は手元のPCでブルートフォース攻撃を仕掛けようにも、肝心のペッパーが分からないため、正しいハッシュ値を計算して照合することができず、攻撃の効率を圧倒的に落とすことができます。

## 3. PHPでの実装例

ここからは、実際にPHPで「ソルト」と「ペッパー」をどのように組み込んで実装するのかを見ていきましょう。

### ① ソルトの実装

PHPには、パスワードハッシュ化の関数 `password_hash()` が用意されています。

```php
<?php
// ユーザーが入力したパスワード
$password = "my_secret_password_123";

// パスワードをハッシュ化する
$hashedPassword = password_hash($password, PASSWORD_DEFAULT);

echo "ハッシュ値: " . $hashedPassword;
// 出力例: $2y$10$e0MYzXyjpJS7P0.v.Kk5xO...
```

`password_hash()` は、**自動的にソルトを生成し、生成されたハッシュ文字列の中にそのソルトを埋め込んでくれます**。
そのため、開発者が自分で「ソルトを別カラムに保存する処理」などを書く必要はありません（レインボーテーブル対策をこれでクリア！）。

詳しい説明は省きますが、ハッシュ化された文字列が以下の形式になっていることで、検証も```password_verify()```でできるということです。

```$[アルゴリズム]$[コスト]$[ソルト(22文字)]$[ハッシュ値本体(31文字)]```

### ② ペッパーの実装

システム共通の秘密の文字列（ペッパー）を環境変数などから取得し、パスワードに結合してからハッシュ化します。

```php
<?php
// 1. 環境変数などからペッパーを読み込む
$pepper = getenv('PEPPER_SECRET') ?: "fallback_secret_pepper_string";

$password = "my_secret_password_123";

// 2. パスワードにペッパーを「結合」してからハッシュ化する
$passwordWithPepper = $password . $pepper;

$hashedPassword = password_hash($passwordWithPepper, PASSWORD_DEFAULT);

// データベースには $hashedPassword のみを保存する
```

検証時も、入力されたパスワードに同じペッパーをくっつけてから `password_verify()` でチェックします。

```php
<?php
$inputPassword = "my_secret_password_123";
$pepper = getenv('PEPPER_SECRET');

// DBから取得した保存済みハッシュ値
$savedHashFromDB = "$2y$10$e0MYzXyjpJS7P0.v.Kk5xO..."; 

// 入力値 ＋ ペッパー を結合して、DBのハッシュと照合
if (password_verify($inputPassword . $pepper, $savedHashFromDB)) {
    echo "ログイン成功！";
} else {
    echo "パスワードが間違っています。";
}
```

## 4. まとめ

* **ハッシュ化の課題**: そのままハッシュ化するだけでは、レインボーテーブルや総当たりで破られるリスクがある。
* **ソルト**: ランダムな文字を混ぜてハッシュ値をバラバラにする（PHPなら自動）。
* **ペッパー**: システム共通の秘密文字をコードで結合し、DBには絶対に入れないことで最後の砦とする！
